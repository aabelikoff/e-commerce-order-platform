Security headers evidence

Goal:

- confirm that the API returns security headers after enabling `helmet`

Checked endpoint:

```bash
curl -i http://localhost:8080/health
```

Observed response excerpt:

```http
HTTP/1.1 200 OK
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Origin-Agent-Cluster: ?1
Referrer-Policy: no-referrer
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
X-DNS-Prefetch-Control: off
X-Download-Options: noopen
X-Frame-Options: SAMEORIGIN
X-Permitted-Cross-Domain-Policies: none
X-XSS-Protection: 0
Content-Type: application/json; charset=utf-8
```

Confirmed security headers:

- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Resource-Policy: same-origin`
- `Origin-Agent-Cluster: ?1`
- `Referrer-Policy: no-referrer`
- `Strict-Transport-Security: max-age=31536000; includeSubDomains`
- `X-Content-Type-Options: nosniff`
- `X-DNS-Prefetch-Control: off`
- `X-Download-Options: noopen`
- `X-Frame-Options: SAMEORIGIN`
- `X-Permitted-Cross-Domain-Policies: none`
- `X-XSS-Protection: 0`

Notes:

- `Access-Control-Allow-Origin` and `X-RateLimit-*` may also appear in the response, but they are not part of the `helmet` security-header evidence itself
- CSP is intentionally disabled in the current setup
- `crossOriginEmbedderPolicy` is intentionally disabled in the current setup
- `/health` is a good endpoint for evidence because it is simple and does not require authentication

Conclusion:

- security headers baseline is present in the running API
- the evidence is consistent with `helmet` being enabled in `src/main.ts`
